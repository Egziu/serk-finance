# 31. AI

**Status:** Designed; no model connection.

| Contract | Definition |
|---|---|
| Entities | EvidenceQuery, AnalysisRun, Proposal, ModelVersion |
| Aggregate boundary | AI analysis/proposal |
| Commands | AnalyzeAuthorizedData, PrepareProposal, RecordReview |
| Queries | CFOExplanation, ForecastEvidence |
| Target domain events | AnalysisCompleted, ProposalReviewed |
| Permissions | ai.analyze with underlying data permissions |

**Value objects and validators.** Use scoped TenantID/CompanyID, immutable UUIDs, expected aggregate versions, typed reference IDs, and effective/as-of dates. Where monetary values occur, use exact Money/Rate and explicit original/functional currencies. Validate aggregate references in the same company and reject missing or ambiguous policy/source revisions.

**Repository and services.** A private AI repository loads and commits the named aggregate; its application service validates the command, invokes explicit cross-domain ports, and commits its state, audit evidence, event/outbox and idempotency receipt atomically where required. Queries respect current actor scope. No other context or extension writes this repository's tables directly. This contract does not create an unimplemented repository class.

**Policies and invariant.** No critical financial authority; citations, confidence and permission-safe retrieval are mandatory.

**Acceptance gate.** Exercise each permitted state transition, forbidden role/company/branch combination, repeated command, stale version, rollback and concurrent conflict. For monetary events, prove source document → expected journal → appropriate control-account reconciliation. Preserve immutable source versions and record the permission/policy decision. Detailed lifecycle/control designs are in the accounting, security, tax, construction, offline and AI architecture documents.
